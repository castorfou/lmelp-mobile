# Issue #158 — Gradle 8.9 → 9.9.0, AGP 8.7.3 → 9.5.1

## Contexte

Le build Android était resté sur Gradle 8.9 / AGP 8.7.3 / Kotlin 2.0.21 / KSP 2.0.21-1.0.27 (dernière montée : issue #10). Gradle 9.9.0 est la version courante. Le sujet avait été soulevé pendant la PR #157 ; la panne 504 rencontrée alors venait de GitHub Releases (castorfou/PyFoundry#133), pas de la version de Gradle.

## Décisions (prises avec l'utilisateur)

- **Gradle 9.9.0 + AGP 9.5.1** (AGP 9.5 exige Gradle ≥ 9.6, JDK 17 suffit : CI et `release.yml` inchangés).
- **Kotlin intégré à AGP 9, sans opt-out** : pas de `android.builtInKotlin=false` ni `android.newDsl=false`.
- **Kotlin 2.4.21** (plugin Compose aligné via `version.ref = "kotlin"`), **KSP 2.3.13** (KSP2 uniquement ; versionnage découplé de Kotlin depuis KSP 2.3).

## Ce qui a été fait

1. **Wrapper** : `./gradlew wrapper --gradle-version 9.9.0` lancé deux fois (la 2e sous Gradle 9.9 régénère `gradle-wrapper.jar`, `gradlew`, `gradlew.bat`). `gradlew.bat` est désormais en CRLF (format produit par Gradle) ; `gradle-wrapper.properties` gagne `retries`/`retryBackOffMs`.
2. **`gradle/libs.versions.toml`** : `agp`, `kotlin`, `ksp`, `room` ; entrée plugin `kotlin-android` supprimée.
3. **`build.gradle.kts`** (racine) et **`app/build.gradle.kts`** : plus d'`alias(libs.plugins.kotlin.android)`. `kotlinOptions { jvmTarget }` (bloc `android`) remplacé par un bloc top-level `kotlin { compilerOptions { jvmTarget.set(JvmTarget.JVM_17) } }` (import `org.jetbrains.kotlin.gradle.dsl.JvmTarget`). KGP 2.4.21 arrive sur le classpath via le plugin Compose, pas besoin de `buildscript { classpath }`.
4. **Exécution de git à la configuration** (`app/build.gradle.kts`) : `ProcessBuilder` → helper `gitOutput(vararg args)` basé sur `providers.exec { isIgnoreExitValue = true }` (null si code retour ≠ 0 ou exception). Lancer un process à la configuration est déprécié depuis Gradle 9 et échouera en Gradle 11. `gitCommit` et `gitChangelog` l'utilisent ; rendu `BuildConfig` identique (vérifié sur device : écran À propos).
5. **Room 2.8.5 (forcé)** : sous KSP2, Room 2.6.1 génère des `*_Dao_Impl.java` qui ne compilent pas (`name clash ... Continuation<? super T>`, « is not abstract and does not override »). Room 2.7+ supporte KSP2 ; pris la dernière 2.x stable (pas Room 3, qui change de package).
   - `LmelpDatabase.kt` : `fallbackToDestructiveMigration()` (déprécié) → `fallbackToDestructiveMigration(dropAllTables = false)`. Vérifié par `javap` sur `room-runtime-android-2.8.5` : l'ancien appel ne positionne que `requireMigration=false` et `allowDestructiveMigrationOnDowngrade=true`, laissant `dropAllTables` à false → comportement identique.
   - `LivresDao.kt` : `RoomWarnings.CURSOR_MISMATCH` → `QUERY_MISMATCH`.
   - Pas de changement de schéma : `ROOM_VERSION` / `PRAGMA user_version` inchangés, pas de release `data-v{N}` à publier.
6. **Kotlin 2.4 : interface imbriquée implémentée par sa classe englobante refusée** (`ARGUMENT_TYPE_MISMATCH` à l'appel, `Navigation.kt:172`). `UserPreferencesRepository.PinnedReadingStorage` sortie au niveau du fichier (`PinnedReadingStorage`, même fichier `data/repository/UserPreferencesRepository.kt`) ; références mises à jour dans `OnKindleViewModel.kt`, `OnKindleScreen.kt`, `OnKindlePinTest.kt` (import `UserPreferencesRepository` remplacé par `PinnedReadingStorage`).
